# CareFlow AI — Feature & Button Testing Checklist

Generated by asking the AI IDE: *"List every feature and button in my second
app that needs testing."* Each item below was manually tested with normal
input, edge-case input, and (where relevant) unauthorized/adversarial input.

## Authentication
- [x] Login form — submit button
- [x] Login — valid credentials (all 3 roles: patient, provider, admin)
- [x] Login — invalid password
- [x] Login — non-existent email
- [x] Login — empty fields (HTML5 required + server-side check)
- [x] Login — rapid repeated failed attempts (rate limiting)
- [x] Register form — submit button
- [x] Register — role selector (Patient / Provider only)
- [x] Register — specialty dropdown (appears only for Provider role)
- [x] Register — full name validation (min length, whitespace-only)
- [x] Register — email format validation
- [x] Register — password strength validation (length, letter+number)
- [x] Register — confirm-password mismatch
- [x] Register — duplicate email (including different capitalization)
- [x] "Log out" button (sidebar and mobile topbar)
- [x] Session persistence on page refresh
- [x] Redirect to `/login` when accessing a protected route while logged out
- [x] Redirect to the correct role's dashboard on login

## Patient Dashboard
- [x] "+ New symptom check-in" button
- [x] Upcoming appointments list renders
- [x] Empty state when no appointments exist
- [x] "Cancel" button per appointment
- [x] Cancelling someone else's appointment via direct API call (blocked)
- [x] Past/cancelled appointments section
- [x] Urgency badge color/label per appointment
- [x] Status badge color/label per appointment

## AI Symptom Intake
- [x] Symptom textarea — character counter (0/2000)
- [x] "Analyze symptoms" button
- [x] Empty / whitespace-only submission (blocked, validation message)
- [x] Very long submission (2000-char cap enforced)
- [x] Normal symptom description → correct specialty/urgency suggested
- [x] Mock analyzer mode (no OpenAI key configured) — source label shown
- [x] Preferred appointment time picker (optional field)
- [x] Past date/time rejected
- [x] "Book this appointment" button
- [x] Redirect to dashboard after booking

## Provider Dashboard

- [x] "Mark completed" button (confirmed → completed)
- [x] Empty state when no appointments assigned
- [x] Attempting to modify another provider's appointment via direct API call (blocked)
- [x] Attempting to cancel another provider's appointment via direct API call (blocked)

## Admin Dashboard (Analytics)
- [x] Stat cards (patients / providers / total / pending / completed / cancelled)
- [x] Bar chart — appointments by specialty
- [x] Pie chart — appointments by urgency

## Admin — Users & Appointments
- [x] Tab toggle: Appointments / Users
- [x] Full appointment list across all patients/providers
- [x] Full user list
- [x] "Deactivate" button per user
- [x] Deactivated user cannot log in afterward

## Cross-cutting
- [x] Sidebar navigation links (all roles)
- [x] Mobile top bar (sidebar collapses under 780px)
- [x] Keyboard navigation: Tab through all interactive elements, Enter/Space activates buttons
- [x] Skip-to-content link (visible on keyboard focus)
- [x] Focus outlines visible on all interactive elements
- [x] Screen-reader labels on all form fields
- [x] Error messages announced via `role="alert"`
- [x] Loading states on every async action (no dead clicks)
- [x] Error states on every async action (no silent failures)
- [x] Unhandled render error → recovery screen instead of blank page
- [x] 404 / unknown route → redirected home
